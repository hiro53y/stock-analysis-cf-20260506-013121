# 株式意思決定支援アプリ — Cloudflare Pages 版

日本株全体から「本日値下がりした銘柄」を集め、**その銘柄自身の過去と比べて割安か**で仕分けて、
買うかどうかの判断材料を1画面にまとめるスマホ対応の Web アプリです。
Android のホーム画面に追加（PWA）して利用できます。

React + TypeScript + Cloudflare Pages Functions 構成。

---

## 画面と機能

| タブ | 内容 |
|------|------|
| **候補抽出** | 日本株全体（約300銘柄）を走査し、本日値下がりした銘柄を**その銘柄自身の過去2年と比べた割安さ**で「買い候補 / 監視 / 割安だが要注意」に仕分けます。各行をタップすると判断材料が開きます。 |
| **個別株調査** | 銘柄コードまたは会社名を指定して、割安さ・価格推移・予測・バックテスト・判断根拠を表示します。 |
| **使用方法** | 用語と結果の見方の説明。 |

### 候補の選び方

1. **一次選抜** — 値下がり率ランキング6ページ + 出来高ランキング2ページ（計8リクエスト）から、
   銘柄コード・社名・市場区分・株価・前日比・出来高を取得します。
   当日下落していて、かつ売買代金が一定以上（＝実際に売買できる流動性がある）銘柄だけを対象にします。
2. **二次分析** — 一次選抜の上位60銘柄だけ、株価履歴（**2年**）を取得します（3リクエスト）。
   割安さ・移動平均・RSI・ボラティリティを計算し、分類とスコアを出します。

この二段構えは Cloudflare Workers の subrequest 上限（無料プランで1リクエストあたり50）に収めるためです。
全銘柄に履歴を取りにいくと上限を超え、キャッシュが切れるたびに 502 になります。
`functions/api/candidates.test.ts` が上限内であることを検証しています。

### 「割安」の測り方

業種平均やPERの絶対水準ではなく、**その銘柄自身の過去2年と比べて安いか**で見ます。
業種によって適正な水準が違ううえ、日本株の業種別集計を無認証で取得できないためです。

| 指標 | 内容 |
|------|------|
| **レンジ内位置** | 現在値が過去2年の終値分布の下位何%か。30%以下を「安値圏」とする |
| **200日線からの乖離** | 長期平均からの乖離率と、**その乖離が過去2年で下位何%の深さか**。同じ-14%でも、荒い銘柄なら普通、おとなしい銘柄なら異常 |
| **52週高値からの下落率** | 高値掴みを避けるための定番の見方 |

3つを合成して割安度スコア（0〜100）を出しますが、**画面では必ず内訳3つを併記**します。

### 分類のルール

スコアの閾値ではなく、言葉で説明できる条件だけで分類します。

| 分類 | 条件 | 意味 |
|------|------|------|
| **見送り** | 当日上昇、または安値圏でない | 今日たまたま下がっただけ |
| **割安だが要注意** | 安値圏 かつ 52週高値から半値以下 | 安いのには相応の理由がある可能性（バリュートラップ） |
| **監視** | 安値圏だが、下落継続リスクが高い / まだ下げ止まっていない | 落ちている最中。下げ止まりを待つ |
| **買い候補** | 安値圏 かつ 下げ止まりの兆し かつ リスクが低い | いま検討する価値がある |

### 目標株価と損切り水準

固定の「+10%」は使いません。その銘柄自身の直近20日のボラティリティから
**約1か月（20営業日）**の想定変動幅 σ を求め、目標 = +1.5σ、損切り = -1.0σ とします。
値動きの小さい大型株と荒い小型株に同じ目標を置いても判断材料にならないためです。

### 過去実績（ベースライン付き）

各銘柄について、**同じ銘柄の過去2年**で安値圏まで下げた日を探し、
その20営業日後の勝率・平均リターン・保有中の最大下落を集計します。

**必ず「条件なしで同じ期間を持った場合」も併記します。** 相場全体が良かった時期なら
何もしなくても上がっているため、その差（実質の上乗せ）を見ないと判断を誤ります。
実測例では、ある銘柄はシグナル時の平均が +8.8% でしたが、条件なしでも +6.3% あり、
実際の上乗せは +2.5% しかありませんでした。

判定は**先読みをしません**。ある日が安値圏だったかは、その日までのデータだけで判定します。
標本が5件未満のときは表示しません。過去の傾向であって、将来を保証するものではありません。

### 銘柄ごとの判断材料（カードを開いたとき）

`GET /api/stock/:code` で以下をまとめて取得します（1銘柄3リクエスト、KVに30分キャッシュ）。

**Yahoo!ファイナンス銘柄ページから**
- PER（会社予想）・PBR（実績）・配当利回り・ROE・自己資本比率・時価総額・**最低購入代金**
- **直近決算の要約**と**〈収益性〉〈安定性〉〈成長性〉の評価**
  — 「なぜ下がったか」に直接答える材料。安くなった理由が業績悪化なら、安値圏でも買うべきではない

**みんかぶから（証券アナリストのコンセンサス）**
- 判断（買い/中立等）・**平均目標株価**・上昇余地
- 人数の内訳（強気買い/買い/中立/売り/強気売り）
- 目標株価の推移（3ヶ月前/1ヶ月前/1週間前/最新）— 直近で引き下げられていればそれ自体が材料
- 今期1株利益の**アナリスト予想と会社予想の比較**

> **アナリスト目標株価は「1年後」の予想**です。アプリ自身の「目標（約1か月）」とは時間軸が違うため、
> 別ブロックに分けて注記しています。**分類やスコアには使っていません**（表示のみ）。

> **Yahoo!ファイナンスのアナリスト評価は使っていません。** `/performance?styl=analystcons` の公開部分は、
> `latestRating` が銘柄によらず同一のダミー値で、推移は6か月前のエントリだけに値が入ります。
> 6か月前の目標株価を出すと実態と大きく乖離するため採用していません。

**アナリストのカバー状態**は3つに分けています。小型株ではコンセンサスが存在しないことが普通にあるため、
「カバーされていない」を「取得できませんでした」と表示しません。

| 状態 | 意味 |
|---|---|
| `covered` | コンセンサスが取れた |
| `none` | 誰もカバーしていない（ページに明記、またはページ自体が404） |
| `unavailable` | 取得・解析に失敗した |

一覧では取得しません。銘柄ページは1銘柄1リクエストのため、60銘柄ぶん取ると subrequest 上限を超えます。

### 外部サイトへのリンク

候補カードを開くと、その銘柄のページを **Yahoo!ファイナンス / みんかぶ / 株探 / 楽天証券 / SBI証券 / moomoo**
で開けます。証券会社のアナリストレポートはログインが必要でアプリ側からは取得できませんが、
ブラウザでログイン済みならリンクから直接読めます。

### 一覧の並び替え・絞り込み

- 並び順: 割安な順（既定）/ 必要資金が少ない順 / 本日の下落が大きい順 / 売買代金が多い順。
  カテゴリをまたいで並びます
- 絞り込み: すべて / 買い候補 / 監視 / 割安だが要注意 / 見送り / 登録銘柄

## セットアップ

### 前提
- Node.js 18 以上
- Cloudflare アカウント（無料プラン可）

### インストールとローカル起動

```bash
npm install
npm run dev:full
```

`npm run dev:full` はビルドしてから Cloudflare Pages のローカルサーバを起動します。
ブラウザで `http://localhost:8788` を開いてください。

### KV Namespace（新しく作る場合のみ）

`wrangler.toml` には既存の Namespace ID が設定済みです。新規に作る場合のみ以下を実行します。

```bash
npx wrangler kv namespace create "ANALYSIS_KV"
npx wrangler kv namespace create "ANALYSIS_KV" --preview
```

出力された `id` / `preview_id` を `wrangler.toml` に記入してください。

## デプロイ

### 方法 A：GitHub 連携（このプロジェクトで使っている方法）

このフォルダ自体が GitHub リポジトリです。変更を push すると Cloudflare Pages が自動でビルド・公開します。

| 項目 | 値 |
|------|-----|
| Build command | `npm run build` |
| Build output directory | `dist` |
| Cloudflare Pages プロジェクト名 | `stock-analysis-cf-20260506-013121` |

### 方法 B：CLI から直接デプロイ

```bash
npm run build
npm run deploy
```

`wrangler.toml` の `name` が実プロジェクト名と一致している必要があります
（食い違うと別プロジェクトが新規作成されてしまいます）。

---

## UI を変更したときの注意

`public/sw.js` の `CACHE_NAME` を必ず上げてください。上げないと利用者の端末に
旧ビルドの app shell が残り、変更が反映されません。
`shared/constants.ts` の `CACHE_VERSION` も対で更新します。

## 制約

- **CPU 時間の余裕が少ない。** 一覧の生成は実測 8.3ms で、無料プランの上限 10ms に対し余裕は 1.7ms。
  本番で `Exceeded CPU time limit` が出る場合は、`shared/constants.ts` の `SHORTLIST_SIZE`（60）を
  下げるか `VALUATION_SAMPLE_STEP`（5）を上げてください。どちらも1箇所の変更で効きます。
- **Yahoo!ファイナンスのHTML構造に依存しています。** クラス名のハッシュは吸収していますが、
  DOM構造が変われば壊れます。壊れた場合は「取得できませんでした」と表示し、数字は作りません。
- **ニュース見出しは表示しません。** Google News RSS は取得できますが、利用条件で
  個人の非商用利用に限ると明記されているため使いません。
- **アナリスト評価はみんかぶのHTML構造に依存しています。** 構造が変われば
  「取得できませんでした」と表示され、数字は作りません。
- **決算発表予定日は表示しません。** Yahoo のフィールドは存在しますが、調査時点では空でした。
- Cloudflare Workers は Node.js の `fs` / `path` を使えません。ストレージは KV のみです。
- バックグラウンド処理はありません。個別分析は同期実行です。
- レート制限は KV の読み取り→加算→書き戻しで実装しており、厳密ではありません
  （同時アクセス時は緩む方向に倒れます）。厳密に止める場合は Cloudflare の Rate Limiting ルールを使ってください。
- 株価データは Yahoo Finance の公開エンドポイントに依存しています。仕様変更で動かなくなる可能性があります。
